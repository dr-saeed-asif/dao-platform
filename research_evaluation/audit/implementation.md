# CyberDAO implementation audit

Reviewed the AI server at `9c27c8a57dfe44abccc43f0cf509ca33e3e0ac79` and DAO platform at `a967659faffdbf9a53afc95c3e63a7dcb665dfaa`. Both source checkouts were clean when inspected. Paths below are relative to the named repository.

| Mechanism | Implementation inspected | Evidence boundary |
|---|---|---|
| UI and API | DAO `apps/web/src/features/ai/proposal-assistant.tsx`, `execution-details.tsx`, `apps/api/src/ai/assistant.controller.ts` | Wallet session, streamed answers, per-worker traces, on-chain comparisons and anomaly table are implemented. This evaluation did not automate the current browser UI. |
| On-chain governance | DAO `packages/contracts/contracts/CyberDAOGovernance.sol` | Owner-restricted create, assign, unassign, and cancel. Vote checks proposal eligibility, option, time and duplicate vote. Finalization has its own state/time conditions and is not owner-only in this contract. Local Ganache suite exercises four scenarios using the existing contract artifact. |
| Planning and dispatch | AI `app/business/agents/question_planner.py`, `planning.py`, `routing.py`, `workflow.py`, `scheduling.py` | Semantic plans, scoped inputs, agent allowlists, bounded scheduler, retry/partial-result behavior and fallback routing are implemented. A text plan is not itself evidence of coverage. |
| Agent inventory | AI `app/business/agents/catalog.py`, `tools.py`, `workflow.py`, `synthesis.py` | Six specialist roles: proposal, evidence, research, governance, blockchain and analysis. Supervisor and synthesis are separate roles. The catalog has 22 entries; catalog membership does not guarantee every tool is invoked or reachable for every question. The Anomalies UI is not a seventh specialist. |
| Evidence retrieval | AI `app/business/governance/retrieval.py`, `document_sync.py`, `evidence.py`, `app/business/rag/indexing.py`, `embedding_profiles.py`, `store.py` | Proposal-scoped retrieval of verified linked PDFs with compatible indexed chunks, plus structured proposal and vote tools. Read-only benchmark connections prevent writes, including automatic re-indexing if needed. |
| Citation checks | AI `app/business/agents/quality.py`, `workflow.py` (`_verify`), `synthesis.py`, `claims.py` | Worker gate checks reference IDs and supported currency amounts, with bounded retry. Synthesis checks task coverage and references, then checks certain numeric and missing-value claims. These rules are not a semantic entailment judge. |
| AI permissions | DAO `apps/api/src/ai/assistant-auth.service.ts`, `assistant.controller.ts`, `blockchain-verification.controller.ts`; AI `app/presentation/api/agents.py`, `app/business/mcp/tool_helpers.py`, `app/business/agents/catalog.py` | Signed wallet authentication, proposal ownership/assignment scope, server bearer credential, and owner-scoped conversation access are implemented. AI tools use scoped reads. Conversation persistence and indexing are application writes, so “read-only AI” refers specifically to governance authority and chain writes. |
| Blockchain consistency | DAO `apps/api/src/ai/blockchain-verification.service.ts`; AI `app/business/agents/blockchain.py` | Block-pinned contract calls, event/receipt comparison and end-of-run snapshot hash check. Database reads are current indexed records. Without temporal alignment and indexer progress, a discrepancy does not establish manipulation or a lost event. |
| History and observability | AI `app/presentation/api/agents.py`, `app/model/database/conversations.py`, `agent_observability.py`, `app/business/evaluation/tracing.py` | Saved chat, task results, execution traces and worker/synthesis tokens exist. Planner API timing is measured externally in the pilot; planner token counters are excluded from reported workflow tokens. |
| Evaluation tools | AI `benchmark/`, `run_benchmark.py`, `app/business/evaluation/experiments.py` | Existing CLI has fixture validation, scoring, repeated-run export and comparison. Its bundled fixtures are not held-out benchmark data. Legacy in-process mode scores specialist outputs and writes evaluation rows; the new pilot measures final answers and exports data independently. |

Experimentally testable contributions are scoped evidence grounding, task planning plus dispatch, auditable evidence/citations, separation of advisory and transaction authority, and reconciliation of indexed state against CyberChain. Causal contribution claims require matched ablations and enough independent proposals. Formal verification, comprehensive penetration testing, robust prompt-injection resistance, and checkpoint-aware anomaly classification are outside what this evaluation establishes.
